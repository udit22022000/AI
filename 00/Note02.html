VARIABLES & OBJECTS

Values are objects; variables are name tags

This is the most important idea in Python. Almost every "weird" thing Python does, from lists changing unexpectedly to is vs ==, is explained by three ideas:

Can't change (immutable)Can change (mutable)
int float bool None str tuple bytes frozenset rangelist dict set bytearray and objects of your own classes

See it in memory

Each diagram has two sides. Left: frames, the workspaces where variables live (global is your file's own workspace; each function call gets its own). Right: the objects in memory. "used by 2" means two arrows point at that object; when nothing uses an object any more, Python deletes it. Pick a scenario and press Step ▶.

The rules these scenarios show

  • b = a never copies anything. It makes b point at the same object as a.
  • Changing a list or dict through one name changes it for every name that points at it.
  • Numbers and strings can't change, so "changing" them really makes a new object and moves the name.
  • Passing a value to a function passes the arrow, not a copy. The function can change your list, but reassigning its own variable doesn't affect yours.
  • del x removes the name x. The object is deleted only when nothing else uses it.
a = [1, 2]
b = a              # same object, second name
b.append(3)
print(a)           # [1, 2, 3]   a sees the change
print(a is b)      # True        is = "the very same object?"
c = a.copy()       # a NEW list with the same items
print(c == a)      # True        == = "equal values?"
print(c is a)      # False       but a different object
print(type(a), id(a) == id(b))   # <class 'list'> True
Dynamic typingVariables have no fixed type. x = 5 then x = "hi" is fine: the name just moves to a different object.
Strong typingObjects never change type silently. "3" + 4 is an error, not "34" or 7.
Everything is an objectNumbers, text, lists, functions, even classes and modules. Each has a type (type(x)) and an identity (id(x)).
Duck typing"If it walks like a duck…" Python cares what an object can do, not what it's called. Anything with .read() can be used like a file.
