HOW PYTHON FREES MEMORY

Cleaning up objects you no longer use

You never free memory yourself in Python. Every object keeps a count of how many references (arrows) point at it. Python adds 1 when a new arrow points at the object and subtracts 1 when an arrow goes away. When the count reaches 0, nothing can use the object any more, so Python deletes it immediately.

The count goes up when…The count goes down when…
you assign the object to a variable: b = athat variable is reassigned (b = 0) or deleted (del b)
you put it in a list, dict or setit's removed from the container, or the container itself is deleted
you pass it to a functionthe function finishes and its local variables disappear
import sys
data = [1, 2, 3]
print(sys.getrefcount(data))   # 2  (data + the call itself)
alias = data
print(sys.getrefcount(data))   # 3
del alias
print(sys.getrefcount(data))   # 2

The one blind spot: cycles

If two objects point at each other, each keeps the other's count at 1 even after your variables are gone, so counting alone would never delete them. Python's garbage collector runs every so often to find and delete such groups:

How the garbage collector decides, step by step

Young (generation 0)Every new object starts here. Checked often, because most objects die young.
Middle (generation 1)Objects that survived one check. Checked less often.
Old (generation 2)Long-lived objects, such as data loaded at start-up. Checked rarely.

Using memory well in everyday code

Let go of what you don't need

A big list or DataFrame stays in memory as long as any variable, list or cache points at it. In notebooks especially, del big_df (or reassign the variable) when you're done with it.

Process data in a stream

Read files line by line (for line in f:) and use generators instead of building huge lists. Only one item has to be in memory at a time.

Pick the right container

Use a set for "is it in here?" checks and a tuple for fixed records. For big numeric data, use NumPy: a million numbers take about 8 MB in a NumPy array, versus about 36 MB as a Python list of ints.

Copy on purpose

b = a shares one object. a.copy() copies the outer list only. copy.deepcopy(a) copies everything inside too.

Don't worry about cycles

The collector handles them automatically; you almost never need gc.collect().

Don't panic if memory doesn't go down

Python usually keeps freed memory to reuse rather than handing it back to the operating system, so Task Manager may still show high usage after a del. It's only a leak if usage keeps growing.
