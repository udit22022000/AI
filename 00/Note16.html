FUNCTIONS

Functions: reusable, named blocks of code

A function packages a few lines of code under a name so you can run them whenever you need, as often as you need, with different inputs. You define it once with def and call it by writing its name followed by brackets.

def area(width, height=1):            # width and height are PARAMETERS
    """Return the area of a rectangle."""   # docstring: describes the function
    return width * height             # send a value back to the caller

print(area(3, 4))                     # 12    3 and 4 are ARGUMENTS
print(area(3))                        # 3     height uses its default, 1
print(area(height=2, width=5))        # 10    arguments passed by name
print(area.__doc__)                   # Return the area of a rectangle.
ParameterThe name in the definition (width). It's a placeholder.
ArgumentThe actual value you pass when calling (3).
returnEnds the function and hands a value back. Without it, a function returns None.
DocstringA string on the first line of the body. help(area) shows it.
def nothing():
    pass
print(nothing())          # None   (no return statement)

def min_max(values):
    return min(values), max(values)   # "several" values = one tuple

lo, hi = min_max([4, 1, 7])           # unpack the tuple
print(lo, hi)                         # 1 7
Return, don't print. A function that returns its result can be reused anywhere: saved in a variable, used in a calculation, tested. A function that only prints it can do nothing else with it.

The kinds of parameters

Python gives you several ways to accept arguments. They can all appear in one function, in this order:

SyntaxNameWhat it does
itemRequiredMust be given, either by position or by name.
qty=1DefaultOptional. Uses the default value if not given.
*extrasExtra positionalCollects any additional positional arguments into a tuple.
gift=False (after *)Keyword-onlyCan only be given by name: gift=True.
**notesExtra keywordCollects any additional name=value arguments into a dict.

Pick a call below to see exactly which value lands in which parameter, and why:

ParameterGetsWhy

# Keyword-only: everything after a bare * must be named
def connect(host, *, timeout=5):
    return f"{host} timeout={timeout}"
connect("db", timeout=10)    # 'db timeout=10'
connect("db", 10)
# TypeError: connect() takes 1 positional argument but 2 were given

# Positional-only: everything before / must NOT be named
def power(base, exp, /):
    return base ** exp
power(2, 3)                  # 8
power(base=2, exp=3)         # TypeError
# Unpacking: spread a list or dict into arguments
nums = [3, 4]
opts = {"height": 5}
area(*nums)        # same as area(3, 4)      -> 12
area(2, **opts)    # same as area(2, height=5) -> 10

# Forwarding everything to another function
def logged_area(*args, **kwargs):
    print("calling area")
    return area(*args, **kwargs)

The mutable default trap

Default values are created once, when def runs, not each time the function is called. A default list is therefore shared by every call:

Bug 
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add_item(1))   # [1]
print(add_item(2))   # [1, 2]   the same list again!
Fix: use None as the default 
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []          # a fresh list on every call
    bucket.append(item)
    return bucket

print(add_item(1))   # [1]
print(add_item(2))   # [2]

Good function habits: give each function one clear job, name it with a verb (calculate_tax, load_users), keep it short enough to read at a glance, write a docstring for anything non-obvious, and pass in what it needs as parameters rather than reaching for global variables.
