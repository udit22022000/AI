Python follows the usual maths order: ** first, then * / // %, then + -. So 2 + 3 * 4 is 14. Use brackets whenever you're unsure: (2 + 3) * 4 is 20.
Converting and rounding 
print(int("42"), float("3.5"), str(7))   # 42 3.5 7
print(int(3.99), round(3.99))            # 3 4       chop vs round
print(round(3.14159, 2))                 # 3.14
print(int("ff", 16), bin(10), hex(255))  # 255 0b1010 0xff
print(abs(-4.5), pow(2, 10))             # 4.5 1024
The math module 
import math
print(math.sqrt(16), math.pi)        # 4.0 3.141592653589793
print(math.floor(2.7), math.ceil(2.1))   # 2 3
print(math.factorial(5), math.gcd(12, 18))   # 120 6
print(math.isclose(0.1 + 0.2, 0.3))  # True

Why 0.1 + 0.2 isn't exactly 0.3

Computers store floats in binary. Just as 1/3 can't be written exactly in decimal (0.3333…), 0.1 can't be written exactly in binary, so Python stores the closest possible value. The error is tiny, but it shows up when you compare or print with full precision. This happens in every programming language.

from decimal import Decimal, ROUND_HALF_UP
print(0.1 + 0.2)                          # 0.30000000000000004
print(Decimal("0.1") + Decimal("0.2"))    # 0.3     exact
print(Decimal(0.1))                       # 0.1000000000000000055511151231257827021181583404541015625
price = Decimal("2.675")
print(price.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))   # 2.68
Rules of thumb: compare floats with math.isclose(), never ==. Use Decimal for money, and always build it from a string (Decimal(0.1) inherits the float's error, as the third line shows). Format floats for display with f-strings: f"{x:.2f}".
